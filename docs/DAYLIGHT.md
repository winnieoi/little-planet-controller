# 白天 / 夜景模式说明

记录「把赛博星球从夜景改成白天」这件事的完整做法，换贴图或调参时看这份。

---

## 一、为什么不能只提亮贴图

两个原因，缺一个都会做砸：

**1. 贴图本身是夜景色相。** 原 basecolor 三通道均值：

| 通道 | R | G | B |
| --- | --- | --- | --- |
| 均值 | 56.9 | 24.2 | 135.1 |

平均亮度 72/255，蓝色是绿色的 **5.6 倍**。这种分布直接做幂律提亮，
暗部颗粒会被一起放大，结果是**一团粉色噪点**，不是白天。

**2. 场景灯全是品红调。** 运行游戏后遍历场景可以看到：

| 灯 | 颜色 | 强度 |
| --- | --- | --- |
| HemisphereLight | `#ff5ef2` | 1.5 |
| DirectionalLight（主） | `#c44dff` | 2.2 |
| DirectionalLight（补） | `#5a7a9a` | 0.6 |
| PointLight | `#ff80d0` | 2.0 |

天空背景是纯色 `#0d0020`，没有雾、没有 environment。
所以贴图提亮后会被这层紫光**重新染紫**，白天感出不来。

## 二、三步流程

### 1. 导出 GLB 里的贴图

```bash
python3 tools/extract_images.py web/models/cyber-planet.glb /tmp/lp-tex
```

得到三张：`basecolor` / `rm`（roughness+metalness）/ `normal`。
只改 basecolor，另外两张保持原样。

### 2. 生成白天版贴图

```bash
python3 tools/daylight_texture.py /tmp/lp-tex/00_*_basecolor.jpg /tmp/lp-day out.png
```

脚本做的是 HSV 域的变换，顺序不能反：

| 步骤 | 目的 | 典型参数 |
| --- | --- | --- |
| 去噪 | 压掉 JPEG 暗部颗粒，否则一提亮全是噪点 | GaussianBlur 0.7~0.9，混回 40~50% |
| 降饱和 + 封顶 | 把霓虹紫压到日光级；**封顶是关键**，不封顶仍会过艳 | ×0.46~0.58，上限 0.30~0.36 |
| 色相偏移 | 离开品红区，往青蓝走 | −20° ~ −34° |
| 提明度 | 最后才提，且用幂律抬暗部、保高光 | ×1.6~1.95，再 `^0.92` |

三套预设（脚本 `presets` 里可直接改）：

| 版本 | 明度增益 | 饱和度 | 色相 | 去噪 | 结果亮度 |
| --- | --- | --- | --- | --- | --- |
| A 清晨微冷 | 1.60 | ×0.52 上限 0.34 | −26° | 0.7 | 165 |
| B 正午晴日 | 1.95 | ×0.46 上限 0.30 | −34° | 0.9 | 190 |
| C 午后暖阳 | 1.75 | ×0.58 上限 0.36 | −20° | 0.8 | 171 |

### 3. 让游戏用上它

两种方式，二选一：

- **运行时替换（推荐，本项目采用）**：贴图放 `web/textures/daylight-*.jpg`，
  由 `web/integration/daylight-mode.js` 在模型加载后替换 `material.map`，
  并同步改灯与天空。可随时切回夜景。
- **写进 GLB**：用 `tools/replace_images.py` 直接替换内嵌贴图，
  生成一个新的 glb。适合只想要白天版、不要切换的场合：

  ```bash
  python3 tools/replace_images.py in.glb out.glb 0=/tmp/lp-day/daylight_A.jpg
  ```

  索引 `0` 就是 basecolor（用 `extract_images.py` 打印的编号为准）。

## 三、灯光与天空的对应参数

| | 夜景（原值） | 白天 |
| --- | --- | --- |
| 天空背景 | `#0d0020` | `#a8c8ea` |
| HemisphereLight | `#ff5ef2` @ 1.5 | `#c6dcff` / 地面 `#d6c9ad` @ 2.2 |
| DirectionalLight 主 | `#c44dff` @ 2.2 | `#fff4e0` @ 3.0 |
| DirectionalLight 补 | `#5a7a9a` @ 0.6 | `#b2c8dc` @ 0.9 |
| PointLight | `#ff80d0` @ 2.0 | `#ffeada` @ 0.9 |

主光与补光靠**原始强度**区分（>1 为主光），因为场景里没有给灯命名。
所有原值都在 `daylight-mode.js` 的 `remember()` 里记下来了，切回夜景逐项还原。

## 四、验证方法

**看接口是否生效**（页面控制台）：

```js
LPDaylight.state            // { mode, variant, sky, fog, glow, ready }
__LP_SCENE__.background     // 白天 -> Texture(渐变) / Color a8c8ea；夜景 -> Color 0d0020
__LP_SCENE__.fog            // 白天 -> { isFogExp2, density: 0.006 }；夜景 -> null
```

**看贴图是否真的换了**（关键，别只看灯光）：

```js
let m = null; __LP_SCENE__.traverse(o => { if (o.userData && o.userData.cyberPlanet) m = o; });
m.traverse(o => { if (o.isMesh) console.log(o.material.map.image.src || "(内嵌)"); });
// 白天 -> daylight-A.jpg   夜景 -> (内嵌)
```

**无头浏览器批量出图**：用 playwright 的 `page.route` 拦截
`**/cyber-planet.glb` 替换成不同变体，再 `page.evaluate` 注入灯光调整，
可以做到**不改任何源码**地对比多个方案。

注意 playwright 默认找的 headless shell 可能没下载，需要指定：

```js
chromium.launch({
  executablePath: "/Users/<你>/Library/Caches/ms-playwright/chromium-1244/chrome-mac-arm64/Google Chrome for Testing.app/Contents/MacOS/Google Chrome for Testing",
  args: ["--no-sandbox", "--use-gl=angle", "--use-angle=swiftshader", "--enable-unsafe-swiftshader"]
});
```

## 五、已知限制

- 白天贴图是**色彩变换**得到的，不是重新绘制。所以色相仍偏淡紫 —— 这是原贴图的
  底子决定的。要彻底自然化只能重画贴图。
- 三张贴图只换了 basecolor。`rm` 贴图里若带自发光的观感，白天模式下会略显扁平。
- 渐变天空是**屏幕空间的背景贴图**，不会跟着镜头转。绕到星球背面时天顶／地平线的
  方位不会变（相当于一张固定背景画），这在球面行走里有轻微的违和感，但考虑到改动
  侵入性，比加真正的 skybox 划算。
- 雾是 `FogExp2`，强弱随距离平方增长。这颗星球半径只有 26 个单位，所以密度要调到
  0.006 这一档才有肉眼可见的效果（详见第七节扫描数据）。

## 六、画质体检数据（1280x800 截图实测）

### 整体亮度：白天没有过曝

只统计星球区域（避开 UI），像素级统计：

| 版本 | 均亮 | 中位 | P95 | 过曝像素% | 暗部% | 均饱和 | 主色相 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 夜景（原版） | 11 | 6 | 35 | 0.16 | 73.9 | 1.00 | 245° |
| 白天 A | 167 | 178 | 206 | 0.16 | 0.01 | 0.29 | 215° |
| 白天 B | 186 | 195 | 214 | 0.16 | 0.01 | 0.22 | 215° |
| 白天 C | 169 | 183 | 204 | 0.16 | 0.01 | 0.26 | 215° |

要点：

- 白天版 P95 只有 204~214，**没有任何过曝**（那 0.16% 是 UI 元素贡献的）
- 暗部占比从 73.9% 直接归零，说明画面整体从"大部分死黑"变成了连续亮部
- 均饱和从 1.00（霓虹纯色）降到 0.22~0.29，符合日光观感
- 主色相从 245°（蓝紫）移到 215°（天蓝），色相偏移方向正确

### 角色可见度：自发光是反效果，别加

用「把自发光开到 1.0 再和关闭状态做差分」的方式可以精确锁定角色像素
（差异区域就是角色，不会被场景里的动画元素干扰）。结果：

| 自发光强度 | 角色亮度 | 周边亮度 | 亮度差 | 色差 | 角色过曝% |
| --- | --- | --- | --- | --- | --- |
| **0（默认）** | 126 | 175 | **49** | **91** | 7.1 |
| 0.38 | 152 | 175 | 23 | 74 | 26.0 |
| 0.6 | 162 | 175 | 13 | 69 | 44.9 |
| 1.0 | 175 | 175 | **0** | 64 | 60.9 |
| 夜景（对照） | 53 | 21 | 32 | 126 | 0 |

**结论：不要给角色加自发光。** 白天浅色地表本身就亮到 175，把角色提亮到同一亮度等于
让它"隐形"，同时过曝会洗掉颜色、色差一起下降。关闭时角色比地表暗 49、色差 91，
比夜景的 32 / 126 还更容易辨认 —— 深色角色落在浅色背景上本来就是可读性最好的组合。

代码里因此把 `GLOW_DEFAULT` 设为 0，机制保留（`?glow=0.2` 可用），但默认不介入。

## 七、渐变天空与大气雾

纯色天空（`#a8c8ea`）虽然不刺眼，但看着像一块贴纸，没有空气感。补了两样东西。

### 渐变天空：拿不到构造器就反查

运行时页面里没有 `THREE` 命名空间，且 commons 里也没有现成的 render target。做法是用
**原贴图所属的 Texture 构造器**（`saved.maps[0].map.constructor`）配一块 4×256 的 canvas：

```js
var g = ctx.createLinearGradient(0, 0, 0, 256);
g.addColorStop(0.00, "#4d84c6");  // 天顶
g.addColorStop(0.42, "#8ab6e2");
g.addColorStop(0.74, "#bedcf2");
g.addColorStop(1.00, "#e2edf5");  // 地平线
```

宽度取 4px 就够 —— 背景是横向拉伸的，只需要竖向有信息。

**还原要点**：之前切回夜景是 `scene.background.setHex(原值)`，换成 Texture 之后这条
路就断了。所以记录时必须存 **Color 对象本身**，不能只存色值。

实测剖面（取画面最左侧纯天空竖条）：

| 屏幕高度 | 渐变版 RGB | 纯色版 RGB |
| --- | --- | --- |
| 顶部 | (73,120,174) | (139,169,199) |
| 1/4 | (99,148,202) | (159,191,224) |
| 1/2 | (118,164,212) | (162,194,227) |
| 接近地平线 | (155,192,226) | (162,194,227) |

渐变版从上到下亮度单调上升 +15 级，纯色版落差为 0。方向正确（天顶深、地平线浅）。

### 雾：用鸭子类型对象顶替 FogExp2

场景里**根本不存在 Fog 实例**，拿不到 `FogExp2` 构造器。但 three 的渲染器判断的是
`isFogExp2` 标志位而不是 `instanceof`，所以普通对象也能生效：

```js
scene.fog = {
  isFogExp2: true,
  name: "",
  color: new saved.colorClass(0xd6e6f4),   // Color 构造器从 scene.background 反查
  density: 0.006
};
```

雾什么时候 open/shut，three 会自己在 `setProgram` 里比对 `materialProperties.fog`，
不需要手动 `needsUpdate = true`。

### 密度不是拍脑袋定的

星球半径只有 26 个单位，镜头通常停在 60~90，所以按常理给的小密度等于没有。以
`fog=0` 为基准逐像素比对了七个档位：

| 密度 | 画面改变均值 | 明显变化像素% | 对比度保留 | 角色亮度差 / 色差 |
| --- | --- | --- | --- | --- |
| 0.0015 | 0.47 | 0.0% | 100% | 15 / 71 |
| 0.0025 | 1.29 | 0.0% | 99% | 15 / 71 |
| 0.0035 | 2.51 | 0.1% | 98% | 15 / 70 |
| **0.006（默认）** | **7.22** | **9.2%** | **94%** | **15 / 68** |
| 0.008 | 12.56 | 25.8% | 91% | 15 / 66 |
| 0.012 | 26.47 | 52.8% | 83% | 14 / 60 |

0.0035 那档画面平均只动了 2.5 个色阶 —— 肉眼看不出来，白给。0.008 开始远景发灰、
对比度掉 9%。**0.006 是"看得出来有空气"又不损失细节的位置**，角色的亮度差（15）
和色差（68）基本没受影响。

### 相关参数

| 参数 | 说明 |
| --- | --- |
| `?sky=gradient` \| `solid` | 天空样式，默认渐变 |
| `?fog=0.006` | 雾密度，0 为关闭 |
| `LPDaylight.setSky('solid')` | 运行时切换天空 |
| `LPDaylight.setFog(0.01)` | 运行时调雾（会重建雾对象） |
